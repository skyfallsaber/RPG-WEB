RPG Web — Estrutura e Organização do Projeto
1. Objetivo da estrutura

Este projeto deve possuir uma arquitetura modular, organizada, escalável e orientada a dados.

A principal regra da arquitetura é:

O código define como o jogo funciona. Os dados definem o que existe no jogo.

O projeto deve ser desenvolvido de forma que seja possível adicionar novos conteúdos e funcionalidades sem precisar modificar constantemente arquivos centrais ou criar arquivos gigantes.

Novos monstros, habilidades, classes, itens, cidades, NPCs, masmorras, eventos e outros conteúdos devem, sempre que possível, ser adicionados através de novos arquivos ou módulos dentro das pastas correspondentes.

3. Arquivos principais
README.md

Documento principal do projeto.

Deve explicar:

O conceito do RPG.
Objetivos do projeto.
Estrutura do projeto.
Regras de desenvolvimento.
Sistemas existentes.
Regras de arquitetura.
Como iniciar o projeto.
Como contribuir.
Informações importantes para futuras IAs que trabalharem no projeto.

O README deve funcionar como o manual principal do projeto.

package.json

Arquivo responsável pelas informações e configurações principais do projeto JavaScript/Node.js.

Deve conter informações como:

Nome do projeto.
Versão.
Dependências.
Ferramentas utilizadas.
Scripts de execução.
Scripts de desenvolvimento.
Scripts de testes.

Não deve conter as regras do RPG.

.env.example

Arquivo de exemplo das variáveis de ambiente necessárias para executar o projeto.

Pode conter referências para informações como:

Banco de dados.
Servidor.
Ambiente de execução.
Chaves necessárias.
Configurações externas.

Nunca colocar senhas ou informações privadas reais neste arquivo.

.gitignore

Define quais arquivos e pastas não devem ser enviados para o Git.

Deve impedir que informações como:

Senhas.
Variáveis privadas.
Dependências instaladas.
Arquivos temporários.
Arquivos de desenvolvimento.
Outros arquivos desnecessários.

sejam enviados para o repositório.

17. Regra fundamental de modularidade

O projeto deve evitar arquivos centrais gigantes.

Não criar arquivos que concentrem todo o funcionamento do RPG.

Evitar estruturas como:

jogo.js
combate.js
habilidades.js
monstros.js
cidades.js

quando esses arquivos começarem a concentrar centenas ou milhares de responsabilidades.

Preferir módulos separados:

jogo/
├── combate/
├── habilidades/
├── personagens/
├── monstros/
├── itens/
├── progressao/
└── geracoes/

Cada módulo deve possuir uma responsabilidade clara.

18. Regra de separação entre código e conteúdo

O código deve responder:

Como isso funciona?

Os dados devem responder:

O que existe?

Exemplo:

O sistema de combate determina como o dano funciona.

Os dados determinam que existe uma habilidade chamada "Bola de Fogo".

O sistema de monstros determina como monstros funcionam.

Os dados determinam que existe um "Lobo Cinzento".

O sistema de cidades determina como cidades funcionam.

Os dados determinam que existe uma "Cidade Inicial".

20. Regra para desenvolvimento com Inteligência Artificial

Qualquer Inteligência Artificial que trabalhar neste projeto deverá respeitar a arquitetura existente.

Antes de criar ou modificar qualquer arquivo, a IA deve:

Entender a estrutura existente.
Identificar o sistema responsável pela funcionalidade.
Verificar se já existe um módulo relacionado.
Evitar duplicar sistemas.
Evitar criar arquivos gigantes.
Manter a separação entre lógica e dados.
Adicionar novos conteúdos nas pastas apropriadas.
Alterar sistemas existentes somente quando necessário.
Não remover funcionalidades existentes sem autorização.
Manter a documentação atualizada quando uma alteração estrutural for realizada.

A IA não deve reorganizar toda a estrutura do projeto sem necessidade.

21. Princípio geral

O RPG deve ser construído pensando em crescimento de longo prazo.

A arquitetura deve permitir que o projeto evolua de:

poucas classes → muitas classes

poucas habilidades → milhares de habilidades

poucos monstros → centenas ou milhares de monstros

uma cidade → um mundo inteiro

um personagem → várias gerações

sem transformar o projeto em uma coleção de arquivos gigantes e difíceis de manter.

O objetivo é:

Adicionar conteúdo sem precisar reescrever o jogo.

Adicionar sistemas sem destruir os sistemas existentes.

Manter cada funcionalidade organizada em seu próprio módulo.

Manter o conteúdo separado das regras.

Construir uma base que possa crescer junto com o RPG.
